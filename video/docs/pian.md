# 四篇

烽火按四条内容线分篇。每一篇是一条独立的内容、短片和游戏路线，朝代长卷只做篇内的筛选。站点入口是 `video/viewer/index.html`（`file://` 可用）。色板与负面词仍按 [art-style.md](./art-style.md)，不另加颜色。

| id | 篇 | 游戏 | 内容 | 短片主线 | 提示词重心 | 配乐 | 页面气质 |
|---|---|---|---|---|---|---|---|
| `zhanchang` | 烽火：战场篇 | 动作 | 战役、列阵、攻守、围城、追奔 | 跟着一场战争走：誓师、旗与尘、战后定格。不生成兵刃相接 | 军阵、旌旗、壁垒、攻城器械、战鼓、号角。朱红只给战旗和血雾 | 鼓由疏到密，号角长音，低弦 | 墨底、斜向笔锋、一道朱砂斜杠 |
| `zhiguo` | 烽火：治国篇 | 策略 | 变法、制度、财政、朝议、盟约 | 跟着一国的经营走：朝会、新政地图、粮仓与渠堰 | 朝堂、奏疏、印章、粮仓、渠堰、典章 | 编钟与古琴，庄严缓慢 | 格网、卷轴双边栏、朱文印 |
| `renwu` | 烽火：人物篇 | 人物技能 | 一个人的出处、选择、关系、晚景 | 跟着这个人走：远行、对坐、独坐、诀别。不画五官 | 剪影肖像、冠帽袖摆、反复的短动机 | 一件乐器上的短乐句反复 | 竖幅卡片、侧立剪影 |
| `dili` | 烽火：地理篇 | 攻城夺城 | 疆域、河流、关隘、城址、道路、边墙如何塑造战事与国策 | 跟着地形走：墨线水系、关口、城郭层次、路线 | 水墨地图、水系、关隘、边墙、城址、行军或漕运路线 | 开阔长音，如风沿着河走远 | 横向长卷、层层灰山、一路墨线 |

同一场可以属于多篇：有一个主篇，最多两个兼收。页面上兼收场会再出现一次，并换用那一篇的提示词。勾选「只看主线」就去掉兼收。

## 数据

不改 `video/data/chapters/*.json`。篇是旁边的一层：

| 路径 | 谁写 | 内容 |
|---|---|---|
| `video/data/pian/series.json` | 手写 | 四篇的名称、游戏类型、范围、提示词重心 |
| `video/data/pian/src/overrides.json` | 手写 | 个别既有场景的主篇 / 兼收，覆盖自动分类 |
| `video/data/pian/src/scenes/<pian>.json` | 手写 | 新场景，不含提示词 |
| `video/data/pian/built/` | `build-pian.mjs` | 分类、新场景、提示词。勿手改 |
| `video/viewer/data/pian/*.js` | 同上 | 查看器用的脚本。勿手改 |

既有场景由 `video/tools/build-pian.mjs` 按玩法模板和标题用字分类。地理只在标题本身讲水利、都城、道路、边墙时做主篇，围城和行军多半兼收地理。

新场景 id 是 `篇.朝代.短名`（三段），避免和既有的 `朝代.短名` 相撞。字段：

```text
id, pian, also[], chapter, title, subtitle,
when { start, precision, display, era, verify, notes? },
line: canon | classic | legend,
narrative, figures[{name, role, en}], places[], placeEn,
sources[{kind, title, section, notes}]
```

`when` 与出处的 `kind` 跟 [content-schema.md](./content-schema.md) 里的 HistoryDate、SourceRef 相同。正史线至少要有一条正史、经典或出土文献；经典线要有经典或正史；传说线的叙事里写明这是传说，或写明和正史的界限。叙事 100–500 个汉字，原创，古籍只引短句。公元年用负数表示公元前，没有 0 年。年号从汉武帝建元（前 140）起写进 `era`；更早写「年号未行」。有争议的地望、设官年份和制度起点写在 `notes`，不写成定论。

提示词由构建器按篇生成，中英各一套，分静帧、视频、配乐、声响，并带负面词。静帧和视频含风格参照、全部色板 Hex、人物剪影规则；视频另含运动约束。四类负面词都含「不出现现代元素」那一句（与 `art-style.mjs` 的 `NEG_MODERN_*` 一致），并含该场所在朝代的时代错置禁令（`negAnachronism(order)`，与场景 `videoPrompt` 相同）。画面里不写字，不画枪械和现代器物；叙事可以提到史书里的火器，提示词不把它们画出来。

## 怎么加一场

1. 把场景对象追加到 `video/data/pian/src/scenes/<主篇>.json`。兼收写在 `also`。
2. 若是改某一场既有场景的归类，写 `video/data/pian/src/overrides.json`：`{ "<sceneId>": { "primary": "renwu", "also": ["dili"] } }`。
3. 在仓库根目录运行 `node video/tools/build-pian.mjs`。
4. `node video/tools/validate.mjs` 必须 0 个错误。校验器要求每篇新场景主线至少 40，提示词带齐风格块、色板、运动约束、现代元素禁令、该朝时代错置禁令，以及上表里的篇关键词。

不要手改 `built/` 和 `viewer/data/pian/`。`build-viewer-data.mjs` 只刷新章节脚本，不会删掉 `viewer/data/pian/`。

开放数据集（Kanripo、NiuTrans、DILA、chinese_history_toolkits、cn-era、Wikidata）可以在本地用来核对年号和纪事，不要提交进仓库。CBDB、CHGIS、殆知阁语料和许可不清的全文库只可当查找线索，不抄进数据，也不随仓库分发。

## 章节开场短片

已经合成的 mp4 仍是朝代片，不按篇重剪。在一篇里选定一个朝代时，查看器播放该朝现成的开场短片；选「全部朝代」时不放。

以后如果为某一篇另做短片，剧本镜头可以加可选字段 `pian`。缺省表示这镜仍属于朝代片。校验器只拒绝写错的 id，不要求旧镜头补字段。新片的静帧、动势、配乐和声响按该篇的上表来写，其余镜长、色板、现代元素禁令和合成步骤仍按 [chapter-videos.md](./chapter-videos.md)。

## 查看器

- `#home`：四篇选择。四张卡片同一骨架（4:5 水墨图、印、篇名、类型与场数、两行范围），差异在图和底下一道笔势。
- `#pian=<id>`：该篇的场景。长卷筛选朝代，可只看主线。「全部朝代」每朝先出 4 场，其余折叠。没有 `sc` 时不自动打开第一场。
- `#pian=<id>&ch=<朝代>&sc=<场景>`：直接打开一场。场景页有「← 朝代」回到列表。选中朝代后，开场短片收在「播放开场短片」里。
- 旧链接 `#ch=&sc=` 会打开该场景的主篇。

既有场景仍显示原来的概要、人物、剧情树、分镜、视频提示词、音频和素材提示词，并多一块「本篇提示词」。新场景显示叙事、人物、地点、出处和本篇提示词，不伪装成已经有剧情树的引擎场景。
