# 通读规划 · 大书分批阅读与上下文管理

目标：任何体量的书都能在上下文有限的环境下完成通读，且不漏事件、不丢页码、不溢出不硬撑。

## 0. 开工前：容量估算

- 转换后的源文本 md 中，1 个汉字（含标点）约折合 1.5–2 token。
- 粗估公式：UTF-8 中文每字约 3 字节 → `字数 ≈ 文件字节数 ÷ 3`；`token ≈ 字数 × 1.8`。
- 量级参考：《万历十五年》（337 页，约 730 KB）≈ 25–30 万汉字 ≈ 45–55 万 token；一般 300 页中文书都在这个量级。
- 以**当前模型上下文安全窗口的 60–70%** 为分母规划总批次数；不要按上限规划，留出写作与校验的空间。

## 1. 分批规则

- 每批源文本量建议控制在安全窗口的 15–25%（示例：安全窗口 20 万 token → 每批读 3–5 万 token 源文，约 1.5–3 万汉字）。
- 分批边界取章节/页码的自然断点（优先按章，章太大再按页）。
- 同一本书绝不一次性整本读入；读完一批只沉淀索引，不提前开写。

## 2. 批内操作：读 → 记 → 落盘

每批固定三步：

1. **读**：用 Read 工具按行号/偏移读取本批段落（注意单次读取的 token 上限，超限就缩小 offset 步长）。
2. **记**：边读边在索引草稿中追加三张索引——
   - 事件表：`时间 | 事件 | 涉及人物 | 页码`
   - 人物表：`人物 | 身份 | 页码`
   - 大事表：`大事 | 页码`
3. **落盘**：每批结束立即用 Write/Edit 把索引写入工作目录 `_索引_<书名>.md`（与三体产物同目录），不依赖对话记忆。

索引条目一律简短（一行以内），只记"关键词 + 页码"，不复制原文长句；同一事件跨批出现时合并为一条并标注全部页码。

## 3. 上下文防溢出

- 不在回复中回显大段原文；引用一律 `〔p.N〕`。
- 已读批次的细节只保留在索引草稿中；后续批次不再重读原文。
- 上下文接近上限时：以索引草稿 + 每批 5–10 条"批摘要"继续，主动丢弃早期原始段落。
- 索引草稿是**唯一事实来源**；写作产物时只依据索引，个别细节定点回查原文页即可。

## 4. 超大书（预计总 token 超过安全窗口 2 倍以上）

- 拆分为**多次会话**完成：每次会话结束前必须把索引草稿与进度文件（已读页码区间、已建索引数）写盘。
- 下一次会话先读索引草稿与进度文件，从断点继续，不重读已读部分。
- 三体产物可分段生成（如长编按分期先写各卷）再合并。
- 若单次会话实在无法完成，如实告知用户已完成进度与剩余批次，不假装完成、不省略校验。

## 5. 校验兜底

- 产物每条页码必须能在索引草稿中找到。
- 索引草稿中归入"年代不详"的条目，写作时不得强行编排年份。
- 人物志与关系网的一致性检查以索引草稿的人物表为准。
