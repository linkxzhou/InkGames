# 史家三体 · 历史书籍三体阅读笔记

把历史类 PDF 书籍转化为三套互为经纬的阅读辅助笔记：**长编体**（编年）、**纪传体**（人物）、**本末体**（大事）。全部产物保留页码以便查证，兼容 Obsidian。

> 长编为经，纪传为纬，本末为鉴。

史家三体，其源有自：

> 古之史策，编年而已，周以前无异轨也。司马迁作《史记》，遂有纪传一体，唐以前亦无异轨也。至宋袁枢以《通鉴》旧文，每事为篇，各排比其次第，而详叙其始终，命曰“纪事本末”，史遂又有此一体。——《四库全书总目》卷四十九“纪事本末类”

本 skill 所产三体，即承此三体史法：**长编**编年以纪时，**纪传**立传以纪人，**本末**具事以纪变。

## 工作流总览

对每一批输入（一本或多本书）执行五步：

1. **收集输入** —— 确认 PDF 路径（一个或多个）。也接受已有的 .txt/.md/.docx 文本或 OCR 结果作为替代输入（跳过第 2 步，直接进入整理）。
2. **转换 PDF → Markdown** —— 逐页提取、保留页码标记，生成 `00_源文本/<书名>.md`。动手前先读 `references/pdf-conversion.md`。若为扫描件且**环境无 OCR 工具、模型也无读图能力**，必须先按该文件 §4 向用户反馈情况与建议并暂停转换，不得强行硬转。
3. **规划性通读** —— 按 `references/reading-strategy.md` 先做容量估算与分批规划，再完整阅读源文本，建立三张索引：事件表（时间/事件/人物/页码）、人物表（主要人物/身份/页码）、大事表（重大事件/页码）。每批读毕立即把索引写入工作目录草稿 `_索引_<书名>.md` 落盘（防上下文丢失）；全部读完再统一写作，不要读一部分就开写、也不要中途放弃。大书宁可分批多次会话，不可上下文溢出硬撑。
4. **生成三体笔记** —— 四份产物（见下节）。
5. **校验与交付** —— 跑检查清单，向用户报告产物路径与统计（页数、事件数、人物数、大事数）。

## 产物目录结构

默认输出到用户指定目录；未指定时输出到书籍 PDF 所在目录，并新建 `三体笔记_<书名或批次名>/` 文件夹：

```
三体笔记_<批次名>/
├── 00_源文本/
│   ├── <书名1>.md           # 每本书一份，保留页码标记
│   └── <书名2>.md
├── 01_长编体_编年史.md      # 时间顺序排列全部事件
├── 02_纪传体_人物志.md      # 主要人物小传 + 关系摘要
├── 03_纪传体_人物关系网.html # 可拖动、可编辑、自包含单文件
└── 04_本末体_大事记.md      # 重大事件提炼 + 疑点
```

同一批多本书合并为一份三体笔记：事件跨书按时间排序，出处标注书名。

> 工作文件（非交付物，交付后可删除）：`_索引_<书名>.md` —— 通读过程中分批落盘的三张索引草稿，是写作产物的唯一事实来源。

## 核心原则（不可违反）

- **严守文本**：只整理书内信息，不得凭外部知识补充或虚构事件、人物、细节。所有条目必须能回溯到页码。
- **页码即证据**：每条笔记都带出处页码；跨书引用写作 `《书名》p.N`。
- **未知不编造**：书里没写时间的事件归入"年代不详"附录，不猜测年份；生卒年书里没有就不写。
- **完整性**：长编覆盖书中全部可确定时间的事件；人物志覆盖全部主要人物；本末覆盖全部重大事件。宁可详尽，不可遗漏。
- **容量可管理**：通读必须分批规划、索引随时落盘；上下文紧张时以索引草稿续读，宁可分次会话，不在溢出状态下硬写。扫描件无 OCR 工具且模型不能读图时，先反馈用户再动手。

## 三体笔记格式规范

### 01_长编体_编年史.md（编年）

效法司马光《资治通鉴》长编：按时间顺序排列全部事件，同一时间多条事件按重要度降序，逐条标注出处。

```markdown
---
title: 长编体 · 《书名》编年史
tags: [史家三体/长编]
---

# 长编体 · 《书名》编年史

> 本编收录书中全部可确定时间的事件，共 N 条。时间以书中纪年为准，公元为换算参考。
> 书中无明确时间的事件见文末"年代不详"附录。

## 速览 · 分期与大事节点
| 分期 | 起讫 | 标志事件 |
|------|------|----------|

## 建安十三年（公元 208 年）

### 正月 · 曹操还邺，作玄武池以肄舟师
- **经过**：……（简洁现代汉语概括，不超三句；书中原文精炼可引原文）
- **涉及人物**：曹操、……
- **出处**：p.123
- **考异**：两书时间记载不一，并列两说存疑

### 某月 · ……
```

要点：
- 时间用书内纪年作标题，公元年放括号；可精确到月/日则标出；不确定写"约/前后/某月"。
- 无法确定先后次序的，排入文末"年代不详"附录，不强行插入。
- 同一事件多书记载不同，在"考异"中并列两说并标页码，不做武断结论；没有分歧就不写考异。

### 02_纪传体_人物志.md（人物）

```markdown
---
title: 纪传体 · 《书名》人物志
tags: [史家三体/纪传]
---

# 纪传体 · 《书名》人物志

> 共收录主要人物 N 位。每人一条：小传、关键事件、关系、出处。

## 曹操（155—220）
- **字号/身份**：孟德 · 魏武帝 · 政治家、军事家、诗人
- **小传**：……（4–8 句概括全书所述生平，只写书中内容）
- **关键事件**：官渡之战〔p.…〕、赤壁之战〔p.…〕
- **关系**：父曹嵩、子曹丕、谋士荀彧、对手刘备、盟友袁绍（后反目）
- **书中评价**：书中所引当时人或作者评语（引原文 + 页码）
```

要点：
- 按重要度排序（君主/主角在前）。
- **人物志与关系网 HTML 的节点、关系必须一一对应**。
- 关系条目注明关系类型（父子/君臣/盟友/对手……），与 HTML 中连线一致。

### 03_纪传体_人物关系网.html（人物关系网）

**复用 `assets/graph-template.html` 模板，不要从零手写**：

1. 读取 `assets/graph-template.html`（已含完整图引擎：拖拽、增删节点/连线、编辑、搜索、阵营过滤、localStorage 自动保存、导入导出 JSON、主题切换）。
2. 把模板中标注的 `const DATA = { ... }` 数据区整体替换为本书数据：节点 = 人物志中的每个人物（含小传摘要、页码、阵营、类型、初始坐标）；连线 = 人物志中的每条关系（含关系标签、类型、页码）。
3. 输出为 `<输出目录>/03_纪传体_人物关系网.html`，模板其余部分（样式与脚本）保持不动。
4. **审美适配**：先判断本书风格（朝代/体裁/封面气质），从模板内置主题中选择或微调 `:root` CSS 变量与字体栈。参考：先秦→青铜、汉魏→漆器朱黑、唐宋→绢本、明清宫廷→金红、近现代→报章。模板顶部有注释说明改哪里；也可在 `DATA.theme` 里指定主题名。

硬性要求：
- 单文件自包含：内联 CSS/JS，**不得引用任何 CDN 或外部资源**，双击即可离线打开。
- 生成后用文本检查器快速验证：无 `http://`/`https://` 外部引用、无 `const DATA` 占位符残留。
- 节点带 tooltip（小传摘要 + 页码出处），供快速查证。
- 字号与自适应：模板已内置大字号基准（`clamp()` 随视口缩放）与窄屏/触屏适配（媒体查询、`touch-action:none`、`100dvh`、触屏加大点击区）。生成时**不得回退缩小字号或删除媒体查询**；修改 `:root` 主题色不影响自适应。

### 04_本末体_大事记.md（大事）

```markdown
---
title: 本末体 · 《书名》大事记
tags: [史家三体/本末]
---

# 本末体 · 《书名》大事记

> 共提炼重大事件 N 起。

## 一、赤壁之战（208 年）
- **时间**：建安十三年（公元 208 年）
- **起因**：……
- **经过**：……
- **结果**：……
- **影响**：……
- **疑点**：
  1. 兵力数字两书记载不一（《三国志》……〔p.N〕；《后汉书》……〔p.M〕）
  2. 火攻计策归属，书中语焉不详
- **待考线索**：可查证的其他篇章页码（只列书中线索）
- **出处**：p.123–128
```

疑点类型参考：史料矛盾、时间抵牾、动机不明、叙事缺环、一书前后不一、后世演绎与正史差异（仅当书内提及时）。没有疑点就如实写"本书未提出明显疑点"，不要硬凑。

## Obsidian 兼容规范（全部 .md 产物）

- 每个文件带 YAML frontmatter（title / tags）。
- 交叉引用用 Obsidian 双链：`[[01_长编体_编年史#建安十三年（公元 208 年）]]`。
- 标签统一 `#史家三体/<长编|纪传|本末>`。
- 页码引用统一 `〔p.N〕` / `〔《书名》p.N〕`。
- 文件名不含空格与斜杠。

## 多本书合并规则

- 每本书独立转 MD 入 `00_源文本/`。
- 三体笔记合并生成：事件跨书按时间排序；出处写作 `《书名》p.N`；同一事件不同书记载在"考异"并列。
- 人物志合并：同一人物合并为一条，关系网络合。
