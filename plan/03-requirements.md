# 03 · 需求说明（InkGames v1）

## 1. 原始需求（原文）

> 创建一个水墨游戏引擎，基于 p5.js + WebGL；参考 inkField（核心引擎 script.js）和 inkwash 的实现。

## 2. 需求细化与解读

| # | 原文要点 | 解读 / 细化 | 依据 |
|---|---|---|---|
| R1 | "水墨" | 视觉核心是**中国水墨画**：墨分五色（焦/浓/重/淡/清）、洇（湿墨在纸上晕开）、飞白（干笔露白）、干边（水痕边缘沉积）、宣纸纤维和颗粒、留白。可选少量设色（花青、赭石、藤黄、朱砂），不是全彩水彩 | 两个参考的强项正好分别覆盖"干笔/书法质感"（inkField）和"湿墨/流动"（inkwash） |
| R2 | "游戏引擎" | 不只是绘画工具，要提供：固定步长游戏循环、场景/实体/组件、输入抽象、相机、资源加载、碰撞（**墨迹能变成可交互的几何**）、事件、存档/回放、调试工具、音频钩子 | 两个参考都没有这些，见 02 §3.3 |
| R3 | "基于 p5.js" | 以 p5.js 为宿主：canvas、WebGL 上下文、`createFramebuffer`、`createShader`、输入事件、2D/3D 绘制 API。引擎用 **instance mode**，不污染全局；游戏代码可以继续用熟悉的 p5 API 画 UI/调试图形 | inkField 用 global mode 带来的耦合问题见 01 §14 |
| R4 | "+ WebGL" | 墨水模拟全部在 GPU 上（浮点纹理、多 pass）；p5 无法提供的特性（MAX 混合、scissor、实例化、浮点格式探测）允许通过 `drawingContext` 直接调用 WebGL2，但要封装成"GL island"并负责恢复状态 | inkwash 用到的 MAX blend / scissor |
| R5 | "参考 inkField（script.js）" | 借鉴它的**笔刷物理、飞白、干笔扩散、身份图、确定性录制、分层视差、性能手段**。**许可证不允许复制或集成它的代码**，所以只按公开文档和读码理解的思想做 clean-room 实现 | 01 §1 |
| R6 | "参考 inkwash" | 以它的**稳定流体 + 湿度门控 + 吸收度颜料 + Beer–Lambert** 作为墨水模拟内核，MIT 授权允许移植代码 | 02 §1 |

## 3. 目标用户与使用场景

1. **独立游戏开发者 / 创意编程者**：熟悉 p5.js，想做"画出来就能玩"的水墨风小游戏（书法解谜、画桥过河、以墨御敌、禅意沙盒）。
2. **交互艺术作品**：展览装置、手机/平板绘画玩具，需要回放、导出。
3. **内部 demo**：引擎自带一个可通关的小游戏和若干示例场景，用来验证引擎能力。

## 4. 功能需求（v1）

### 4.1 墨水与渲染
- F-INK-1 稳定流体墨水模拟：速度、压力、湿度、活动颜料、固定颜料多场；sim/dye 双分辨率。
- F-INK-2 吸收度颜色模型 + Beer–Lambert 显示；纸色、纸纹（纤维/齿）、边缘加深、颗粒。
- F-INK-3 干燥与固定：随时间自然干燥；API 可以强制固定一个区域或全部。
- F-INK-4 白色（胡粉）覆盖层。
- F-INK-5 干笔局部扩散 pass（inkField 的 `min()` 思想）和飞白遮罩。
- F-INK-6 材质 / 身份图（MaterialMap）：每个像素记录"是哪种墨/哪个实体留下的"，和颜料一起被平流。
- F-INK-7 环境力场（风、水流）：程序化噪声场叠加到速度场。
- F-INK-8 程序化"墨精灵"（ink sprite）：把位图/矢量轮廓以墨的方式渲染（用于角色、道具），支持浓淡、晕边动画。

### 4.2 笔刷与笔画
- F-BR-1 笔尖跟随：弹簧阻尼或指数跟随（可配置），与帧率无关。
- F-BR-2 速度/压力 → 粗细与墨量；没有压感时用速度模拟。
- F-BR-3 笔刷预设：至少 **毛笔（湿）、枯笔（飞白）、细笔（勾线）、水刷（只加水）、泼墨（喷溅）、白笔** 6 种。
- F-BR-4 笔画对象：点序列（x, y, pressure, t）、包围盒、长度、墨量消耗；笔画结束事件。
- F-BR-5 笔画 → 碰撞几何（胶囊链/折线），供游戏判定。
- F-BR-6 墨量（ink budget）：作为游戏资源。

### 4.3 游戏框架
- F-GM-1 固定步长主循环（默认 60Hz）+ 插值渲染。
- F-GM-2 场景（Scene）+ 实体（Entity）+ 组件（Component）+ 系统（System），轻量 ECS 风格。
- F-GM-3 输入：鼠标/触摸/笔统一为 Pointer，支持压感、侧键、手指与笔区分；键盘；动作映射。
- F-GM-4 相机：2D 平移/缩放/跟随/震动，视差层（z-planes 思想）。
- F-GM-5 资源：场景 JSON、纸张预设、笔刷预设、颜料表、图片（ink sprite 源）、音频。
- F-GM-6 简易 2D 物理：圆、AABB、胶囊链（笔画）碰撞；重力、反弹、触发器。v1 自己写，不引入大型物理库。
- F-GM-7 事件总线：`strokeStart/strokeEnd/inkDried/collision/trigger/sceneLoaded`。
- F-GM-8 存档与回放：记录输入事件 + seed，确定性重放（同一设备、同一质量档）。
- F-GM-9 音频钩子：提供事件 → 回调接口（例如笔速映射到音量），v1 不做音频引擎。

### 4.4 工具
- F-DBG-1 调试面板：FPS、各 pass 的 GPU/CPU 耗时、纹理内存。
- F-DBG-2 buffer 查看器：wet / ink / fixed / velocity / pressure / materialMap 的伪彩色显示。
- F-DBG-3 无头确定性测试（`?demo` 模式）：固定输入脚本 → 截图 → 和基准图做差异比较。
- F-DBG-4 参数热调（lil-gui 或自研），可导出成预设 JSON。

## 5. 非功能需求

| 编号 | 要求 | v1 目标 |
|---|---|---|
| NF-1 性能 | 桌面 1080p | 60fps，sim ≤ 5ms/帧 |
| NF-2 性能 | 近两年中高端手机/平板 | 60fps（dye 1024 / sim 256）；低端安卓下限 30fps（dye 512 / sim 128） |
| NF-3 兼容 | 浏览器 | Chrome/Edge ≥ 120、Safari ≥ 17（iOS/macOS）、Firefox ≥ 120；**必须 WebGL2**；没有浮点渲染时降级（见 05 风险） |
| NF-4 确定性 | 回放 | 同设备、同质量档：笔画几何与游戏逻辑 100% 一致；像素级允许极小误差（GPU 浮点） |
| NF-5 体积 | 引擎包 | 不含 p5 时 gzip 后 < 150KB |
| NF-6 可维护 | 代码 | TypeScript strict；核心模块单测覆盖率 ≥ 70%；没有全局状态；不混淆 uniform 名 |
| NF-7 内存 | GPU | 移动端纹理总量 ≤ 64MB，桌面 ≤ 256MB |
| NF-8 许可 | 依赖 | 只用 MIT/BSD/Apache/LGPL（不修改、以独立文件动态链接）的依赖；**不包含 inkField 代码** |

## 6. 不在 v1 范围内

- 3D 场景（easycam 那种自由旋转）、WebGPU 后端、联网/多人、关卡编辑器 GUI（v1 只用 JSON + 沙盒）、spectral 光谱混色、inkField 风格的 flow 8 种后处理和金属效果、超大世界的分块流式加载、视频导出、音频引擎。
