# 06 · 规划审查与细化执行计划（2026-10-08）

> 依据本仓库 `plan/01`–`05` 与 `thirdparty/inkwash/index.html`、`thirdparty/inkField/LICENSE`、`thirdparty/inkwash/licence.txt` 本地快照核对。本文件保留首次审查时的范围与估算；**2026-10-08 后续已确认桌面优先、水刷必须改变碰撞几何、微内核+插件；当前实施决策请以 [07](./07-microkernel-plugin-plan.md) 为准**。这里只修订计划，不实现引擎。

## 1. 结论与必须修正的事实

总体技术方向成立：p5 承载草图和画布，WebGL2 做模拟；inkwash 的场模型适合湿墨，inkField 的不可移植实现只能借鉴通用概念；游戏判定应使用 CPU 几何而非 GPU 像素。不过现有 14 周计划把大量高风险特性同时列为 Must，不宜直接照此承诺发布。

1. **湿度纹理位置写错**：`02` §2 和 `04` §3.3 把 `wet` 记在 sim。原版 `inkwash/index.html:546–555` 实际把 wet 按 **dye 分辨率**分配；`index.html:840–850` 也使用 wet 自己的 texel 尺寸。已修正 `02` 中该项；`04` 的字段、图示、预算在后续决策后统一修订。若改为 sim 分辨率，是新算法设计而非原样移植，须比较边缘细节。
2. **流体 pass 顺序不一致**：`02` §2.1 写 curl→涡量→投影→速度平流，`04` §4 也是类似顺序；原版 `index.html:793–838` 是 **速度平流→curl→涡量→散度→压力→梯度扣除**，然后湿度/颜料平流及 exchange。M2 对照原版时必须按原始顺序实现；变更顺序单独评测。
3. **“自然干燥即固定”不是原版行为**：`index.html:867–881` 中 `settle = fixing ? 1-exp(-5dt) : 0`。原版通常只降低湿度，不把活动颜料自动转入 fixed；`fixDrawing()` 才启动 1.2 秒固定过程。`03` F-INK-3、`05`《墨渡》的“干后成实体”需要独立的 CPU 湿/干计时和明确的自动固定规则，不能依赖原版 exchange 自动实现。
4. **性能/内存估计偏乐观**：medium 1024×1536 时，一张 RGBA16F 为 12 MiB；ink 双缓冲 + fixed 双缓冲 **48 MiB**，wet 双缓冲 R16F **6 MiB**，Material RGBA8 双缓冲 **12 MiB**；三项已达 **66 MiB**，尚未计 sim、纸纹、渲染输出、视差纹理、深度缓冲及浏览器开销。`05` §3.3 中“sim 场 <3MB”漏算 wet 所在分辨率，fixed “改用临时 + swap”仍须两张目标，除非临时纹理可在时间线上被严格复用且永不同时存活。64 MiB 必须通过计算完整生命周期峰值和真机验证，而非只算场纹理。
5. **融合算法需要重新定义**：`min()` 适用于“白底灰度，墨越深数值越小”；在 Beer–Lambert 的非负吸收度中应是 `max()` 或其它明确的沉积算子。直接对 absorbance 使用 `min()` 会擦掉墨；即使用 `max()` 也可能凭空增加颜料，不适合作为守恒流体扩散。飞白优先在**笔尖沉积阶段**做遮罩，湿墨扩散与干边分别处理。
6. **p5 与原生 GL 混用风险高于当前表述**：仅恢复 blend/scissor/viewport/FBO/program 不足以隔离状态，还要考虑 VAO、ARRAY_BUFFER、active texture/绑定纹理、颜色写掩码、blend func/equation（RGB/alpha）、像素存取状态等，以及 p5 自身的状态缓存。原生 GL 负责多场模拟时，建议它拥有完整的 FBO/shader/pass；p5 只作 canvas、输入/可选 UI 宿主，不要为每个 pass 在 p5 与原生 GL 之间来回切换。M0 之后再确定兼容层边界。
7. **描述自相矛盾**：`03` 要求风场、InkSprite、自动降级等功能，而 `05` 把其中部分放 Should；`04` API 固定提供尚未保证的 `RGBA8_PACKED` / PBO/fence / `sample()`；`04` §1 “引擎不碰 DOM”与 `parent: HTMLElement`、输入/画布管理不一致。待 M0 结束后重新冻结公开 API，仅为已实现功能签约。
8. **文档定位已过期**：`README`、`01`、`02`、`04`、`05` 写参考源码在 `/workspace/inkgames/ref/` 或称未查 `thirdparty/`，但本地已有 `thirdparty/inkField/`（含 `.git`、源码、p5.js 等）及 `thirdparty/inkwash/`。引用本地路径并确认快照 commit；参考源码留在仓库只读目录，不进入构建、发布包、示例资源或制品。`inkField/LICENSE:8–30` 禁止再分发/衍生；如计划公开发布当前含 inkField 快照的仓库，应先移除/隔离受限快照或获得授权（仅改构建入口不等于可以再分发）。这不是法律意见。

## 2. 建议的 v0.1 范围重定

**核心交付：**单屏游戏坐标、单实例、一个实时墨层，湿笔/干笔/水刷三种笔刷；墨与纸的黑白表现，湿度驱动的扩散和可视化固定；Pointer 输入；60 Hz CPU 逻辑和可重复的录制；可画桥/挡板的胶囊链与圆形墨珠碰撞；单屏《墨渡》教学关；诊断视图。p5 只管理一个 WebGL2 canvas/context，不产生额外图形 context。

**第二批（先满足核心门槛）：**白笔覆盖、有限设色、纸性对照、相机缩放、一个烘焙视差背景、另外两关、三设备档位。按可测需求增加，避免首先设计完整 ECS：v0.1 用 `Scene + Entity + Component` 及顺序系统即可，扩为通用 ECS 留给 v0.2。

**延期或明确删除接口：**完整 MaterialMap 与颜料 ID 平流（多墨混合后单 ID 本身不明确）；InkSprite 千实体目标、风场同时作用 GPU/CPU、PBO/fence 采样、RGBA8_PACKED 高精度模拟、自动降档、六笔/八颜料全套、跨设备像素哈希、连续多层实时墨、录像体积硬限制。仅在证实确实支撑《墨渡》之后升级；低设备在无可渲染 16F 时先给出明确能力缺失信息或提供独立简化的 8-bit 视觉模式，不承诺等价流体。

## 3. 需在设计冻结前确定的契约

- **坐标：**场景与碰撞以 world CSS px 为唯一单位；相机只变换 world↔screen，指针按 canvas DOMRect、DPR 和相机逆矩阵回到 world；墨场 world→UV（含 Y 翻转）与渲染相机同源。初版 world=单屏固定尺寸，resize 改显示比例不改变世界/碰撞；尺寸变化、设备旋转测试线条与物理体是否对齐。不得把短边 1024 当成每层都固定 1024：长边和总像素数另设上限。
- **时间和输入：**每帧采集原始 pointer/coalesced events（有则使用），每固定步消费全部落入窗口的样本，排序并做路径距离重采样；记录步号、步内顺序、按固定精度量化的世界坐标/压力、笔刷与参数变更。无输入时仍执行湿度干燥；逻辑时钟/录制时钟不随渲染帧率改变。积压超过最大步数时定义“暂停并追赶/显式丢步”的录制语义，绝不能静默让回放时间和关卡时间分叉；后台/失焦暂停并记录恢复事件。
- **笔画几何：**原始点保留用于录制，显示点可平滑，碰撞胶囊由同一条 CPU 路径按距离阈值和每点宽度形成；RDP 简化限制几何误差、长度和细分次数。碰撞成形按 CPU 中的 `release` 或 `dryAtStep`，不要等待 GPU fixed 的读回。水刷如果只改变 GPU 像素，已建立的碰撞体不改变；若玩法要求“冲开笔画”，必须同步修改 CPU 笔画分段和墨量，否则从 demo 描述中去掉此机制。
- **干燥：**决定“湿”与“固体”的 CPU 规则按每笔计时（或压力/纸性/水刷触发的解析模型）定义；像素 wet 仅驱动画面。原版 `fixDrawing()` 与自动固定需拆成不同命令；自然干燥到固定层的区域/混合比例先做实验，避免在不停落墨时整屏一键沉降。
- **GPU：**内部格式探测必须逐一建纹理、挂 FBO、`checkFramebufferStatus`、画入/读回、检查精度和采样过滤；启用 `EXT_color_buffer_float` 不是支持证明。16F LINEAR、MAX 浮点 blending、context lost/restore、resize 时销毁旧 GPU 对象均须实测；p5 shader 与 GLSL 300 es 适配同一项 M0 决策。实例化 splat 必须按目标/混合规则分批（ink/velocity 用 ADD，wet 用 MAX，material 用显式覆盖），不能用一次 draw 同时对不同场采用不同混合语义。
- **合成：**墨场 dirty 由 splat、干燥、每次模拟 step、相机/尺寸/后处理参数变化驱动；即使停止输入，湿度或残余速度仍变化时不得误跳 composite。静止并达到阈值后才休眠；重绘 UI 和移动相机可重用模拟结果。p5 的 `draw` 负责调度固定步及一帧一次的屏幕呈现。
- **录制：**保存版本、引擎兼容版本、world 尺寸、seed、笔刷/场景快照或内容哈希、模拟频率/质量参数和用户动作。游戏逻辑只消费 CPU 可重放状态；视觉对比采用容差/统计，不要求不同 WebGL 驱动像素相同。质量档动态切换需留记录并允许重新初始化场；首版回放过程中锁档。

## 5. 逐项验证矩阵

| 项目 | 最小方法 | 通过条件 | 失败时的动作 |
|---|---|---|---|
| p5 版本/API | 锁定实际使用版本，打印 WebGL context、shader/FBO 能力；对比 1.x 与候选 2.x 仅在 G1 进行 | 一个版本在三类设备上稳定；不能把“当前最新版 2.3.1”当长期事实 | 原生 WebGL2 接管 pass，p5 保持宿主；仍不可行则评估 p5 版本兼容层或缩平台 |
| 纹理可用性 | 对 R16F/RG16F/RGBA16F 各执行 FBO 完整性、读写、LINEAR 与重复小量累积测试 | 无 GL error、精度达到阈值、浏览器真机稳定 | 每种格式分别调整；不用“扩展存在”替代渲染测试 |
| 混合和 splat | 原版逐个 splat 与按 ADD/MAX 分桶的批量 splat 输入相同脚本 | 覆盖率、湿度及力在阈值内相近，叠画无饱和异常 | 回退到逐 splat + scissor，再优化批处理 |
| 墨迹物理同步 | 画桥、跨边界、释放、等待干燥、用水刷修改笔画后滚动物体 | 游戏物理状态完全遵循声明的 CPU 规则 | 简化规则，移除视觉改变会同步改变物理的暗示 |
| 内存 | 逐张记录宽高、B/px、存活区间、目标池生命周期，测 resize 与双实例峰值 | 移动端 64 MiB 仅作为**纹理预算**；实际 GPU 资源/页面内存需真机余量验证 | 先降 dye 长短边/删材质图与视差缓存，不以临时纹理“复用”虚减峰值 |
| 时钟/回放 | 30/60/144Hz 显示、丢帧、休眠恢复，比较按步量化的笔画/碰撞/通关哈希 | CPU 逻辑一致；GPU 用统计范围而非严格像素哈希 | 修复输入/步长策略，录制不通过前不发布 |
| 帧预算 | GPU timer 扩展可用时测各 pass，禁用时记录 CPU submit 并以真机 FPS 验证；采样空闲/连续书写/发热 5min | 桌面核心场景目标 60fps；移动端目标与最低设备先由 G0 锁定，不在 G1 前保证手机 60fps | 优先限制 dye 总像素和 pass 数，再调整 sim/迭代数，必要时下调公开指标 |
| 版权/发布 | 审计打包文件、开源仓库、示例资源及许可证全文 | inkwash MIT 声明完整；无 inkField 受限源码和资产公开再分发 | 移除受限快照/停止公开发布并寻求授权；作独立法律复核 |

### 纹理预算计算范例（medium，1024×1536，1 MiB=1,048,576 B）

| 场 | 算式 | 大小 |
|---|---|---:|
| ink 双缓冲 RGBA16F | 2×1024×1536×8 | 24 MiB |
| fixed 双缓冲 RGBA16F | 2×1024×1536×8 | 24 MiB |
| wet 双缓冲 R16F | 2×1024×1536×2 | 6 MiB |
| material 双缓冲 RGBA8（**如启用**） | 2×1024×1536×4 | 12 MiB |
| sim：velocity 双缓冲 RG16F，pressure 双缓冲 R16F，curl/divergence 各 R16F（256×384） | (8+4+2+2)×256×384 | 1.5 MiB |
| **仅上述场合计** | 不含 final/post/paper/资源和驱动开销 | **67.5 MiB** |

对于核心交付，先不启用 MaterialMap，场纹理变成约 **55.5 MiB**，仍须输出缓冲、纸、浏览器/驱动开销；因此绝不能将 64 MiB 写作已兑现的移动端总量。`inkwash` 的 wet 在 dye，宽高还取决于窗口比例（`getRes()` 按长短边比例扩大）：横竖屏与屏幕像素必须同时限制。当前 `05` §3.3 关于“固定层不用 double 即可省内存”只在证明原始数据仍可安全读且目标池重用后才成立。
