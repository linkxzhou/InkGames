## 1. 结论与范围

**当前引擎能做水墨笔画与叙事播放的基础，但不能据现有能力认定它能自动生成参考画面级别的完整历史动画。推荐“美术图片锁定画面 + three.js 分层运动 + InkSurface 局部实时水墨”的混合路线。**

- 程序负责墨滴、笔触、局部洇染、收笔、镜头、字幕与时间线；图片负责历史人物、复杂构图、服饰、建筑、山水细节和大规模军阵。
- three.js 是渲染与合成工具，Matter.js 是二维物理工具，均不是根据剧本生成画作的模型。剧本和 `artPrompts` 完成不等于素材、动作与成片完成。
- 目标先调整为“历史流程动画播放器”，不是先补齐所有横版动作玩法；保留未来游戏入口，不把战斗、AI、马匹操控等列为本轮阻塞项。
- 本轮只生成计划，不修改引擎、故事正文、章节 JSON 或参考资源。

### 三种制作模式

| 模式 | 适用内容 | 取舍 |
|---|---|---|
| 纯程序水墨 | 抽象混沌、落墨、飞白、地图路径、转场 | 可参数化，但不能保障复杂人物与构图 |
| 图片 + 引擎（默认） | 人物叙事、山水、开天补天、战争 | 美术稳定；补分层、遮罩、运动与资源管线 |
| 预渲染视频后备 | 低性能设备、复杂运动、固定成片发布 | 降低运行成本；分支边界和字幕仍由宿主管理 |

原图只作为风格/构图参考；素材的使用、裁切和发布需先确认权利，不能默认 `thirdparty/` 的图片可直接打包。

## 2. 当前能力：以代码而非规划名称为准

| 能力 | 实际证据 | 判断与限制 |
|---|---|---|
| three.js 水墨面 | [InkSurface](../src/core/ink-surface.ts)：paint、begin/add/end、update、wash、snapshot/restore、replayEffect | 已有实现，可复用；局部墨面反馈不等于整幅画作生成 |
| 多层展示与镜头 | [StoryStage](../src/core/story-stage.ts)：PlaneGeometry + InkSurface.texture；[CameraRig](../src/core/camera-rig.ts) | 有分层 Z 与整体推拉平移；没有图片资源图层和逐对象动画轨道 |
| 叙事与六轨播放 | [CutscenePlayer](../src/core/cutscene-player.ts)、[SceneDirector](../src/core/scene-director.ts)、[StoryRuntime](../src/core/story-runtime.ts) | 有笔画、镜头、文字、效果、音频、同步；示例只载入易水寒单包 |
| 地形洇染、山石、竹 | [TerrainSeep](../src/core/terrain-seep.ts)、[皴法材质](../src/core/cun-material.ts)、[竹](../src/core/bamboo-rig.ts) | 横版切片能力；StoryStage 不会因 JSON 写 terrain 就创建真实地形，也未挂接两个叙事事件 |
| 人物和道具 | [stroke-cues](../src/core/stroke-cues.ts)、[prop-paintings](../src/plugins/prop-paintings.ts) | 有通用 figure 等笔画预设，不是盘古、女娲等专属造型或动作系统 |
| 图片加载和运动 | [narrative-types](../src/core/narrative-types.ts)：layers 只有 inkPlane/terrain/screen，tracks 无图片/对象运动轨 | 本轮核心缺口；artPrompts 不会被运行时直接渲染 |
| 音频与文字 | [AudioBus](../src/core/audio-bus.ts)、[InkText](../src/core/ink-text.ts) | 基础实现可复用；真实配音、BGM、书法美术与字体授权另行制作 |
| 缓存/回看/导出 | 墨面有 snapshot；CutsceneDef 有 bake；播放器有 fastForward | 不是完整关键帧缓存、任意 seek、离线逐帧导出或视频后备系统 |

### 必须先修的播放正确性问题

1. **live 笔画参数与并发**：`StoryStage.paintPulses()` 的 live 分支没有像 instant 分支那样应用 stroke 的 brush/color/finish；一个 InkSurface 同时接收多个 LiveRun，存在 begin/add/end 相互干扰风险。需先定义同层串行、临时墨面或明确拒绝并发的策略，并测试末点是否确实提交。
2. **跳播不等于正常播放**：`CutscenePlayer.fastForward()` 只返回 instant 和新 begin 转换后的笔画；中途进行中的笔画、跨越的效果、墨面 update 过程不能保证与顺播同结果。当前 `StoryStage.fastForward()` 也未逐帧应用这些中间效果。需通过检查点 + 有界重放重建目标帧。
3. **宿主不是严格 60 fps**：`apps/story/main.ts` 每次 RAF 按 gap 执行 1 或 2 步，没有 60 Hz 累加器；高刷新率与卡顿可能改变播放时长。需统一帧钟、暂停语义与最大追赶步数。
4. **效果字段未完整兑现**：fade/freeze/暗角已有；flow/distort/metallic 为墨面事件。shape 的矩形/多边形遮罩、target 的完整语义、frames 的持续动画不能视为已支持；景深参数被计算但未在 StoryStage 展示。inkDisperse/bambooBreak 也未连接。
5. **恢复不是任意帧自动可靠**：当前恢复依赖事先采集的 snapshots；自然上下文丢失后的最近画面、活动笔画、图片与效果状态均需设计检查点与重放方案。

6. **真实音频播放仍缺运行时能力**：`AudioBus.play()` 目前始终调度振荡器/短音，没有按 asset 加载、解码与播放音频文件；`voEnded()` 用逻辑帧估算结束，不是实际音频结束事件。仅补录音文件不能完成接入，淡入淡出、crossfade、duck 也需兑现。
7. **运行时解析是浅校验**：`content-catalog.ts` 主要检查格式、版本和轨道数组，再作类型断言；不能据此认定每个 cue、资源引用、数值范围和能力均已校验。新增 presentation 必须有运行时深校验，并将离线内容结构校验与运行时能力预检分开。

上述属于代码审阅发现与风险，未以新增测试重现；实施时先建立回归用例，再确定修复边界。现有 snapshot 只含 final/typeMap/wet 和 frameCount，不含完整笔刷、活动笔画、随机与中间反馈状态；不得直接当作任意帧可续播检查点。首版只在笔画提交且反馈稳定的边界建检查点，其他位置从前一安全点重放。

## 3. “混沌开卷”先做垂直切片

源数据：[上古章节](./11-history-game-data/chapters/00-shanggu.json)，场景 `shanggu.hundun`，开场 `cutscene.shanggu.hundun.opening`。原时间线 **5400 帧 / 名义 90 秒**，沿用现有五段旁白与分镜，不擅自压成短片。镜头采用半开区间 [from, to)，同步等待可延长实际播放时长；导出须显式选择按真实旁白插入等待帧或固定 90 秒编排，不能默认两者完全等价。

| 段落 | 原帧区间 / 秒 | 剧本目标 | 推荐画面实现 |
|---|---|---|---|
| s1 | 0–600 / 0–10 | 白纸、一点墨落下并晕开 | 统一纸底 + 实时墨滴/局部扩散；可叠加批准的混沌墨团纹理 |
| s2 | 600–1560 / 10–26 | 人形浮出、撑开上下 | 盘古专属透明立绘，遮罩显影；天地图层分离运动。需要真实肢体动作时用分件绑定或预渲染，不用缩放立绘冒充撑天 |
| s3 | 1560–3000 / 26–50 | 清升为天、浊沉为地 | 上下云墨层反向缓移 + 山水图片分层 + 局部雾/水纹 |
| s4 | 3000–4680 / 50–78 | 天缺、洪水、女娲炼石 | 天缺遮罩、女娲立绘、洪水和火光局部层；烟与火只在对应区域运动 |
| s5 | 4680–5400 / 78–90 | 五色石补天、一笔收住 | 透明五色石/补天图层 + 缺口遮罩闭合 + 实时收笔；保持配色克制与原文语义 |

**当前 JSON 的语义落差**：s1 从第 0 帧就画远山，第 240 帧画云，没有专门的落墨事件；盘古和女娲使用同一个 figure、同一 placement，缺少身份造型与动作；火借 ink-bomb 表达，补天借 water-brush 路径表达。近山、水与人物多为累积笔画，没有相应退场/切镜清理。旁白和分镜存在，但画面只是粗略占位。

本轮补独立 presentation 覆盖数据，按 shot/id 对齐图片、运动与效果，**不改写旁白、史源、分支与年代**。开场后的 choice 保留；gameplay 节点在动画模式下用明确的讲述段落或人工继续策略承接，不宣称已经运行玩法，也不自动给玩家发放玩法通关成绩。

## 4. 混合动效管线

```text
现有章节/剧情/字符串表（只读） + presentation（分镜表现数据）
  → 资源预检与加载 → CutscenePlayer 统一帧状态
  → 图片平面 / 局部墨面 / 粒子与遮罩 / 屏幕文字
  → StoryStage 合成 → 可选 PostStack → 显示或逐帧导出
```

### 4.1 分层素材规范

- 正式资源放 `apps/history/assets/<chapter>/<scene>/`，表现数据放 `apps/history/presentations/`；`src/` 只放通用能力，不导入章节业务数据。
- 每镜头建议先控制在 4–8 个视觉图层，动态 InkSurface 只用于确需画/洇染的区域；不为每个图片建立一套全尺寸墨面。
- 单件人物、器物、烟雾、浪花采用保留 alpha 的 PNG/WebP；纸底只保留一份。整图有纸纹时不再叠第二层强纸纹。
- 抠图不得按纯白阈值删掉所有白色：飞白、衣纹、高光与留白不都是背景。检查黑底/纸底两种合成，修掉白边、暗边与矩形透明边界。
- 分层视差需足够出血与遮挡补画；保持主体原比例。人物面部、手和器物不参与全屏噪声位移。
- 每件资源声明 id、路径、像素尺寸、色彩空间、alpha 约定、pivot、逻辑尺寸、来源、许可和替代资源；镜头另声明 transform、z、blend、mask。
- 原素材网格与 `artPrompts` 是制作中间物，不等于运行时资产；优先完成样例镜头的高质量素材，不先批量制作全部 4343 件。

### 4.2 通用能力增量（均为拟议，非已实现 API）

| 能力 | 建议落点 | 最小交付 |
|---|---|---|
| 资源管理 | `src/core/story-assets.ts` | 图片预加载、尺寸/许可清单校验、失败替代、释放与恢复；音频仍交 AudioBus |
| 图片平面 | `src/core/story-image-layer.ts` | 不透明背景与透明主体、pivot、层序、透明混合与尺寸；与 InkSurface 图层共存 |
| 对象运动 | 扩展 narrative-types / CutscenePlayer / StoryStage | layer/object 的位置、scale、opacity、rotation 关键帧；帧状态可直接求值，不累计积分漂移 |
| 局部显影 | `src/core/post-stack.ts` 或专用图片材质 | 墨噪声 reveal、rect/polygon mask、局部位移；明确坐标系与作用域 |
| 局部特效 | `src/core/story-fx.ts` 或对应通用插件 | 云/雾/水/火星等首批预设，种子固定；不为每朝代写一套核心类 |
| 真实音频 | 扩展 AudioBus | asset 加载/解码/播放、实际结束事件、首次交互解锁、暂停/seek 偏移、总线淡化与 duck；无音频时明确字幕后备 |
| 状态重建 | 播放器与墨面检查点 | seek/skip/restart、活动笔画、累计效果、随机状态及资源恢复 |
| 预览与导出 | `apps/history/` 与 `scripts/` | 选章选场、播放/暂停/逐帧/跳镜、关键帧截图；随后实现离线帧序列/视频 |

新增公共接口从 `src/index.ts` 导出，后续实施同步对应 docs 与 plan/10 状态。新增 GPU、监听器与计时资源遵守资源登记及幂等 dispose；补齐图片 mesh 的 geometry/material/texture 释放，不能只释放 renderer。

### 4.3 数据兼容策略

先采用独立 `inkgames.presentation` 表现文件：关联 sceneId、cutsceneId，声明 assets、imageLayers、motions、reveals、fx、checkpoints 和静态后备。保留现有六轨契约，不把图片假装成笔画。

- 命名使用稳定的 assetId/objectId/layerId/shotId；帧范围与原 CutsceneDef 对齐，60 fps。
- 区分世界图层和屏幕图层：镜头移动不应带走字幕、题字安全区与 UI。
- 明确覆盖而非双重绘制：声明 replace/additive 模式及按 cue ID 或明确索引绑定的禁用清单；盘古/女娲图片替代 figure 时，禁用相应原笔画，不能让旧占位人物继续累积。禁用列表越界、原数据变化或内容版本不匹配时拒绝加载；原六轨数据保持只读。
- 静态对象值与运动关键帧可直接按帧求值；累计水墨反馈依赖检查点和完整重放。
- 首版固定使用原 1280×720 逻辑坐标，1920×1080 仅是输出分辨率；定义原点、Y 方向、pivot 单位、局部/世界遮罩及透明排序。图片 sRGB 解码后在线性空间合成，再统一输出，禁止墨面与图片重复色彩转换。
- 关键帧同帧冲突有确定顺序；seek 重建可见状态但不重播跨越的音效、选择、成就或存档副作用。恢复旁白/BGM 时按目标时间偏移播放；结束 skip 与普通 seek 分开定义。
- 校验存在的引用、唯一 ID、非负帧、合法作用域/混合方式、运动覆盖范围、资源尺寸上限；不支持的字段报错或显式降级，禁止静默忽略。
- 老场景无 presentation 时仍按原笔画模式播放。先完成样例后再决定是否合入下一版 CutsceneDef；不一次改造 157 场景。
- artPrompts 是创作建议，不是 runtime 合约；正式资产 manifest 与提示词来源分离。

### 4.4 墨感与运动边界

图片显影使用“原图 alpha × reveal mask”，保留原笔触；局部低频位移只影响雾、水和墨团。全幅持续扭曲会使山、人物和纸纹像橡胶，不能作为通用水墨效果。

现有 InkSurface.replayEffect 处理的是自身墨面，**不能假定加载一张图片后就会自动进入同一墨反馈管线**。P0 首选图片材质显影 + 独立透明墨面叠加；图片导入墨面并参与 feedback 的能力需要独立设计与验收，放后续。

旗帜、衣摆可用局部网格形变或分件绑定；复杂骑马、交战、撑天等动作优先序列帧/预渲染，不用静态图平移替代动作。战争远景优先静态军阵画层 + 局部尘雾、旗动、少量前景剪影；Matter 只在需要刚体碎片时启用，且服从统一时钟。

## 5. 实施顺序与完成门槛

| 批次 | 工作 | 完成门槛 |
|---|---|---|
| P0-A：播放基础 | 帧钟、live 参数与并发、skip/seek 语义、未知能力诊断、检查点策略 | 30/60/120 Hz 宿主测试下逻辑时长一致；同层多笔画不串色/串路径；跳播无遗漏事件 |
| P0-B：一个混合镜头 | 确认参考和授权；准备 s1/s2 最少素材；图片层、运动、显影、统一纸底 | 原图主体风格保留，至少两层独立运动、局部实时墨效；不是整图仅缩放的幻灯片 |
| P0-C：90 秒混沌开卷 | 实现五镜头 presentation、人物替换/退场、天缺补天、音频同步、回看 | 原旁白与五段语义逐镜对齐；无旧人物残留、贴图白框或字幕随镜头漂移 |

## 6. 验收与性能预算

### 6.1 美术验收

先由所有者批准五张参考的风格标注及每镜头一张目标关键帧，再比对成片。观察主体轮廓、构图留白、焦/浓/淡墨层次、枯笔飞白、边缘洇染、点缀色、纸纹和字幕可读性；不以“有噪声/有 shader”替代审美验收。

混沌需看到落墨、人形浮出、天地分离、天缺洪水炼石、五色石补天与收笔的明确因果；原图不含这些信息时必须补素材，而不是仅添加摄像机运动。楚汉需检查时代服饰/器物和军阵重复感；具体视觉判断仍待人工核图。

### 6.2 正确性验收

- CPU 测试：轨道求值、资源引用、同步点、分支、未知效果诊断、帧钟、并发笔画、正常播放与 seek/skip 的状态一致性。
- 同环境同种子重复播放：比较指定关键帧；图片/对象状态应一致。GPU 墨面给出差异统计与容差来源，跨浏览器不承诺逐像素一致。
- 中途暂停/恢复、回到上一镜头、直接进入 s4、结束跳过、缺图片/音频、自然上下文恢复均有明确行为。
- 模拟 WEBGL_lose_context 只是一项冒烟测试；检查点重建应与未丢失路径在目标帧比较，不能仅验证“恢复了画布”。

### 6.3 性能目标（待真实 GPU 实测，不是现有成绩）

桌面 Apple Silicon + Chrome 为首批验收环境，记录机器/GPU、浏览器、分辨率与质量档。目标 1920×1080 输出、稳定 60 fps，展示帧 p95 ≤ 16.7 ms；低档允许 30 fps 展示但保留 60 Hz 逻辑或切视频后备。首次可见静态预览目标 ≤ 2 秒，动画启动本地热缓存目标 ≤ 3 秒；冷网络加载另外计量。

优先保留人物图像分辨率，降低雾/装饰特效分辨率、更新频率、粒子数量和活跃墨面数。**累计反馈的 InkSurface 不得直接跳过逻辑 update**；降低其更新频率会改变成像，应作为独立质量变体重新烘焙并验收，不能沿用高档检查点。只冻结已经稳定提交的墨面。所有阈值在混沌样例跑真实 GPU 后修订。

动画模式采用独立观看进度，不写玩法 cleared/grade；章场浏览不受玩法成绩锁死。选择、讲述替代节点与汇流由表现映射显式定义，缺少映射时停下提示，不自动猜测剧情走向。

RGBA8 单张 1280×720 约 3.5 MiB、1920×1080 约 7.9 MiB；InkSurface 内部有多张目标，不能把其成本当作一张纹理。统计全部 RT、图片、深度缓冲与检查点 CPU 内存；先定内存预算再开放更多图层。闲置墨面冻结更新，跨场景及时释放，预加载限制在当前与下一场景。

### 6.4 验证入口与发布红线

后续每批实施执行 `./build.sh check`、`./build.sh build`；预览通过 `./build.sh dev`。无头 WebGL 只证明编译与错误状态，不证明真实观感或性能。离线导出工具尚未实现，不提供假定可用的导出命令。

发布前逐件检查图片、字体、音频、分层衍生与视频后备许可；不直接复制受限参考快照或素材，不修改 thirdparty，不为本计划安装新依赖。

## 13. E0 首步：live 笔画调度修复（2026-10-09 继续执行）

`StoryStage.paintPulses` 的 live 分支原来没有设置笔刷/颜色、也不校验序列，并且同一墨面可被多个活动笔画同时写入。本轮：

- `begin` 现在 `setBrush` + `setColor` 后再落第一点；缺 `point` 视为非法。
- 每张墨面只允许一个活动笔画；同一层重复 `begin`、游离 `point`/`end`、以及活动笔画期间插入 `instant` 都会被拒绝并计入 `rejectedPulses`（新增只读 getter），不再静默串色或串路径。这比原行为更严格，编排必须让同层笔画串行。
- 正常 `end` 会执行 `update()` 提交末点；`StrokePulse.endOfStroke` 标记真正的收笔，只有此时才 `replayEffect`，避免每次 end 重复施加 flow/distort/metallic。
- 新增 `tests/cutscene-pulses.test.ts`（3 项）：单次 begin → 有序 point → 单次收笔并只应用一次收尾；单点笔画也会正常收笔；跳播把 live 折叠为 instant。

**仍未完成**：`CutscenePlayer.fastForward` 不重建中间效果与墨面 update 过程，跳播结果仍不等于顺播（需要 G-08 安全点重放）；`StoryStage` 不做多边形遮罩与景深；`wash` 效果仍以固定半径作用于画面中心。这些不得写成已完成。

`./build.sh check` 通过（15 个测试文件、97 项）。

## 13b. E0 第二步：墙钟帧钟与进位（2026-10-09 继续执行）

实测发现 `/history/` 播放只有约 **0.5 倍速**：原来每次 RAF 按 gap 取整步数，而 60 Hz 的 gap 常略低于 16.67 ms，约一半回调取整为 0 步，时间被丢掉。

- 新增 `advanceFrameClock(frame, carry, dt, durationFrames, budget)`（`src/core/fixed-clock.ts`，已导出）：按真实经过时间推进 60 Hz 逻辑帧，**携带小数进位**，只在超过工作预算（`FRAME_CLOCK_MAX_STEPS = 90`，gap 上限 2 s）时才丢时间并置 `dropped`。
- 与玩法用 `advanceFixedClock` 的区别：玩法封顶 4 步以保稳定性，帧钟不封顶以保证成片时长；两者语义在注释中写明。
- `/history/` 宿主改用该帧钟，并保存/重置 `carry`；状态栏在丢帧时显示计数。
- 新增 `tests/frame-clock.test.ts`（7 项）：慢机不慢放、进位而非取整、抖动平均后精确、到片尾夹取与不倒退、超预算丢弃并标记、0.3 s 慢帧下 10 次推进恰好 180 帧。

**实测**：无头 SwiftShader 下 8.0 s 墙钟推进 8 帧秒（ratio 1.000），修复前约 0.5；无 JS/shader 错误、无图片请求。

**仍未完成**：该帧钟只保证逻辑帧数贴合墙钟；渲染仍可能在慢机上跳帧，`dropped` 只统计超预算情况；`CutscenePlayer`/`StoryStage` 尚未接入此帧钟；任意帧安全点重放仍未做。

`./build.sh check` 通过（16 个测试文件、104 项）。

## 16. 核对补记（2026-10-09 同轮，修正脚本缺陷）

核对过程中发现并修好两处**真实缺陷**（不是文档问题）：

1. `scripts/gpu-check.mjs --shots` 的最后一步仍在等已删除的 `/compare/parity.html`，会先超时 3 分钟再失败。已改为对 `/history/` 截四个关键帧（0 / 1200 / 3800 / 5300），并复用「零图片请求」断言。实跑通过。
2. `apps/scroll/` 的帧步长未钳下界，首帧 rAF 时间戳可能早于捕获的 `performance.now()`，使 `Playfield` 收到负步长并抛 `Invalid frame dt`（复现率约 1/4 启动）。已钳到 `[0, 0.05]`。

另新增确定性回归：`window.__historyHash(frame)`（`apps/history/main.ts` 暴露，只读像素、不改播放状态）与 `scripts/browser-smoke.mjs` 的断言——同一帧连续渲染两次逐字节一致，不同帧必须不同。这补上了 §6.2 要求的一部分，但仍不等价于「两次播放末帧逐像素一致」，因为后者要求整条反馈路径在两次独立播放中收敛到同一像素。

以上三项都属「先修脚本与宿主，再谈计划勾选」，已并入 §15 的已完成表。
